# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Tool calling, end to end. The model can reach for four tools on its own now: `web_search`, `web_fetch`, `read_file` and `ocr`. The client sends the tool definitions with every request, runs whatever the model asks for, feeds the result back as a `role: "tool"` message, and lets the model carry on. The answer stays a single message, and every call shows up in it as a card with its arguments and its result. The upstream turned out to speak the standard OpenAI tool protocol all along: it answers with `delta.tool_calls` (arguments streamed in pieces) and `finish_reason: "tool_calls"`, and it accepts the tool result that follows. The README used to say tool calling was not supported; that line was wrong, and both READMEs now carry what was actually measured.
- Four tool endpoints on the proxy, under `/tools/`: `search`, `fetch`, `ocr` and `document`. They are plain HTTP and touch no files, so the same code runs on Cloudflare Workers, Vercel Node, Deno Deploy and Node.
- A search tool with three backends, tried in this order: a self-hosted SearXNG (`SEARXNG_URL`), the Brave API (`BRAVE_API_KEY`, 2000 queries a month for free) and the Tavily API (`TAVILY_API_KEY`, 1000 a month for free). With none of them configured the proxy falls back to reading the Bing result page — no account, no key, but a fallback and not a promise. The repository ships a ready-to-run SearXNG in `proxy/searxng/`; its `settings.yml` has the one line that matters, `formats: [html, json]`, without which the JSON API answers `403`.
- A document service, `proxy/doc_service.py`, that turns documents into text and reads the text out of pictures. Documents go through MarkItDown (PDF, `.docx`, `.xlsx`, `.pptx`, and the older `.xls`); pictures go through RapidOCR, which is the PaddleOCR models in ONNX form — the same accuracy, four times faster on a CPU, a fifth of the memory, and no PaddlePaddle to install. A scanned PDF, whose pages are pictures, is rasterised with pypdfium2 and then read by the OCR, twenty pages at the most, and the rest is reported as not read. The service is optional: without it everything else keeps working and the two tools that need it answer that the service is not running.
- Attachments. The composer takes files now. Text is read in the browser and never leaves the machine; PDF, Word, Excel and pictures are handed to the document service when a tool asks for them. The names of the attachments travel with the message, so the model never has to stop and ask what the files are called. They live in memory only — a refresh loses them, and the tool says so.
- A chip at the bottom-left of the composer that switches the tools off. Off means the request carries no `tools` and the model just talks.

- A workflow that hosts the proxy on a GitHub Actions runner, `.github/workflows/tunnel.yml`: it starts one run every four hours (`cron: 17 */4 * * *`), lets each run live for at most 5.5 hours (`timeout-minutes: 330`), installs `cloudflared`, starts the local proxy with the key read from the repository secret `VITE_API_KEY`, opens the tunnel, and publishes the resulting address into the `tunnel-url` file on the `runtime` branch. The run fails when the runner cannot reach the origin: the workflow probes `/__ping` and requires `"reachable": true` in the answer. The workflow sets no concurrency group, so a new run starts alongside the previous one instead of cancelling it or queueing behind it; the previous round stays up for another 1.5 hours after the new one takes the pointer, so the handover leaves no gap.
- An upstream pointer in the proxy, `UPSTREAM_POINTER`: the proxy fetches a publicly readable text file at runtime and uses its content as the upstream. The result is cached for thirty seconds, and a failed read keeps the last address that worked instead of taking the proxy down. `proxy/wrangler.toml` points it at the `tunnel-url` file on the `runtime` branch.
- A `runtime` branch, an orphan branch that holds nothing but the `tunnel-url` file the pointer reads.
- A tunnel launcher, `proxy/tunnel.mjs`, wired to `npm run tunnel`: it starts the local proxy, opens a Cloudflare quick tunnel to it, and writes the resulting `trycloudflare.com` address into the repository variable `VITE_PROXY_URL` with the `gh` CLI before triggering the Pages deployment. The tunnel address changes on every restart, and the site follows it automatically.
- A Vercel entry point on the Node runtime, `proxy/api/[...path].js`, with `proxy/vercel.json` rewriting every path onto `/api/:path*`. The project root is `proxy/`. Node rather than Edge, because an Edge function runs on an edge node and only a real container can be relied on to reach a bare IP on a non-standard port.
- Conversations are named automatically. The first user message is turned into a short title locally, so the list always has a name to show; once the answer is done the model is asked for a better one, through a small request with thinking off, a token cap and a twelve-second timeout. Any failure leaves the local title in place, and a title the user typed by hand is never overwritten.
- Renaming and pinning for a conversation. The sidebar title can be edited in place — Enter commits, Escape cancels, thirty characters at the most — a conversation can be pinned into a group of its own above the date groups, and rename, pin and delete are all reachable from a right-click menu on the conversation row.
- Copying an answer in two shapes. The button itself copies plain text; the arrow next to it opens a menu with "Copy" and "Copy as Markdown". A plain-text copy drops the heading marks, the emphasis, the list bullets and the code fences, and keeps a formula as its LaTeX source.
- Editing a question. The pencil button on a user message loads it into the composer; sending it drops that message and everything that came after it, and asks the model again.
- A fold for the desktop sidebar. The button at the top-left of the main area collapses it to zero width, and the choice is remembered across visits.
- An automatic retry when the upstream is full. This upstream takes one request per IP — a second one comes back as `429` with `code: "concurrency_limit"`. That is a queue, not a failure, so the client now waits a minute and tries again, up to five times. The message says which attempt it is and how many seconds are left, and the stop button cuts the wait short. When the queue does not move, the message says so plainly instead of waiting forever.

### Changed

- The proxy forwards `/tools/*` to the tunnel when it runs as a front door (`UPSTREAM_POINTER` is set), because the document service only exists on the machine at the other end of the tunnel. A deployment that is the only hop answers the tool paths itself.
- The default deployment path is now the Actions-hosted proxy behind a fixed Cloudflare Worker address, instead of a proxy on a machine somebody has to keep running. Actions minutes are free for a public repository, so this costs nothing and needs no account. `VITE_PROXY_URL` still means "the public address of the proxy", and in that setup it points at the Worker, whose address does not change when the tunnel does: a new tunnel address reaches the Worker within thirty seconds and neither the Worker nor the site has to be redeployed.
- The project is now a chat client for exactly one model, `dsv4-flash`, and both READMEs say so. The generic OpenAI-compatible framing is gone.
- The connection target is decided at build time instead of at runtime. `src/config.ts` is the single source of truth for the origin URL, the model id, the API key, the default reasoning effort, and the sampling parameters.
- `VITE_PROXY_URL` selects the endpoint: when it is set every request goes through that proxy, when it is empty the request goes straight to the origin. In development an unset `VITE_PROXY_URL` falls back to `http://127.0.0.1:8787`, the local proxy, so a fresh clone runs with `npm install && npm run proxy && npm run dev`.
- `VITE_API_KEY` injects the API key at build time. The repository holds no real value.
- The settings panel is gone. Only the theme and the reasoning effort remain adjustable, and both are reachable directly from the interface: the theme from the icon button at the bottom of the sidebar, the reasoning effort from the chip at the bottom-left of the composer.
- The reasoning effort chip now offers all five levels: off, none, low, high, and max.
- The empty state is reduced to the product name. The onboarding guide, the introduction copy, and the suggested questions are gone.
- The API key table in the READMEs now lists two locations instead of three, and the claim that the frontend probes `/__ping` before sending its own key was dropped: the proxy injects the key server-side and overrides whatever the client sent.
- The README deployment chapter now tells you to set the repository variable `VITE_PROXY_URL` to the public address of your proxy — the Worker address in the default setup, the tunnel address, the Vercel or Deno Deploy URL, or the address of your own server — instead of telling you to type a proxy address into the interface.
- Both READMEs and `proxy/README.md` no longer present Cloudflare Workers as a way to run this proxy. The upstream is reached over TLS at a bare IP whose certificate names only that IP, and the Workers edge refuses to connect to it: `error code: 1003` for the bare IP, `526 Invalid SSL Certificate` for a hostname that points at the same address, and the free plan cannot do TLS over `cloudflare:sockets`. The proxy therefore has to run on a machine with unrestricted network access — the Actions runner, the quick tunnel, Vercel on the Node runtime, Deno Deploy, or a self-hosted Node server. The Workers deployment files stay in `proxy/` and still apply to an upstream that has a domain name. Against this upstream the Worker is used the other way round: as the fixed entry point in front of the tunnel, which it can do because it only has to fetch an ordinary hostname.
- The README deployment chapters now describe three hosting options in the order they are worth trying — GitHub Actions (default, free), your own server / Vercel / Deno Deploy, and your own machine plus a tunnel — and the Quick Start now starts from the published site already working, because the reader no longer has to run anything to get a working chat.
- The reasoning panel is now a fixed-height viewport instead of a plain overflow box. The thinking text scrolls up inside a window capped at eight lines or thirty percent of the viewport, whichever is smaller, and the top edge is softened with a gradient mask rather than cut off hard. While the model thinks, the window stays pinned to the newest line; scrolling up pauses that follow and floats a "back to the latest" button into the corner, and scrolling back down resumes it. A blinking caret sits at the end of the text and a breathing dot next to the timer in the header; when the thinking ends the dot turns into a check, the panel folds itself back into a single summary line, and the header reads "thought for X.X seconds".
- Every visit opens on a fresh conversation. The welcome screen is what the app starts on, and the earlier conversations are one click away in the sidebar. Empty conversations are not written to local storage, so they cannot pile up over time.
- The message list follows new output to the bottom. A new turn jumps straight to the newest line, and while the answer streams the view stays pinned there; scrolling up pauses the pin rather than fighting for it, and a floating button brings the view back.
- Upstream errors are written for people now. The machine wording was passed through verbatim, so a full upstream read as "too many concurrent requests from your IP (limit 1); wait for the running one to finish" and a missing key read as an HTML page from nginx. Each known case now has a sentence that says what happened and what to do: a 429 explains the provider's parallel limit of one, a 401 explains where the key belongs, a 502 from the proxy names the broken hop and mentions that the origin sits inside the country, so a direct connection from abroad may need a VPN. The upstream's own words are kept underneath, in smaller type, for the times the friendly sentence is not enough. An error that arrives inside the stream instead of in the status line is now recognised too, instead of the stream quietly ending and the message blaming a dropped connection.
- Body text, the composer and the reasoning panel breathe a little more: the line height goes from 1.6 to 1.75, and the space between list items grows from 0.35em to 0.5em.
- The welcome screen writes its own name. The title appears letter by letter — each glyph fading in out of a blur, 62 milliseconds apart — a hairline caret blinks while the name is being written and then puts itself away, and a thin gold rule draws itself underneath. All of it is CSS: no JavaScript runs per character, the animation replays whenever the screen comes back, and readers who ask for less motion get the finished page instead of the writing. The title is set in the serif face the project already self-hosts, and the paper wash behind it is the only gradient in the interface.

### Removed

- The whole settings panel: connection mode, proxy URL, origin URL, API key input, model name, temperature, top_p, max_tokens, system prompt, and font size.
- The SetupGuide card that explained how to reach the service, together with its three deployment paths.
- The connection status badge (untested, connected, latency) and the token usage bar.
- The client-side token estimate that was shown under each message.
- URL hash encoding of conversations, and the confirmation card that went with it.
- Exporting a conversation as Markdown.
- The model name label and the hint line under the composer.
- The "connection not tested yet" notice.

### Fixed

- The proxy no longer dies when a request fails in the background. An unhandled rejection used to take the whole process down, and in production that is the whole site: a search that timed out was enough to take the chat offline. The Node runner now logs it and keeps going.
- The tunnel now hands over to itself instead of relying on GitHub's scheduler. The `cron: 17 */4 * * *` schedule in `.github/workflows/tunnel.yml` never fired for this repository — neither the 12:17Z nor the 16:17Z slot on 2026-11-20 produced a run — so every round was killed at its five-and-a-half-hour limit with nobody taking over and the site sat dark, answering `HTTP 530 · error code: 1016` or `1033`. Each round now starts its own successor ninety minutes before it runs out, using the repository's own `GITHUB_TOKEN`; `workflow_dispatch` is exempt from the rule that `GITHUB_TOKEN`-triggered events do not create a run. The cron stays as a backstop, and a backstop-triggered round stands down when the tunnel the pointer names is still alive, so the two never fight over the pointer. The workflow also takes two inputs when started by hand: `takeover` (`auto` or `always`) and `handoff_now`.
- Long answers and long thoughts are no longer cut off in the middle. The upstream counts `reasoning_content` against the same `max_tokens` budget as the answer, so thinking hard ate the whole budget and left the answer nothing: measured against this upstream, a deep reasoning task at `max_tokens: 4096` spent all 4096 tokens on thinking and produced not a single token of answer. `MAX_TOKENS` is now `131072`. The upstream takes that value without complaint and does not check it against the context window either, and the value is a ceiling rather than a target — a side-by-side run had the model write a shorter answer under the larger ceiling.
- A cut-off response is no longer presented as a finished one. The client now tracks the upstream's `finish_reason` and whether the stream ended with a termination marker, and a truncated message carries a notice that tells a token-budget cut, a dropped connection, and an upstream filter apart. Previously every one of them looked like a normal completed answer.
- The upstream's `finish_reason` is read before the delta, so a last frame that carries no `delta` no longer swallows the termination reason.
- The Vercel entry point asks for 300 seconds instead of 60. Vercel kills a function at `maxDuration`, and a long think easily runs past a minute.
- The "thought for X.X seconds" readout now measures the thinking itself. It used to report the delay before the first reasoning token arrived, which against a fast upstream came out close to zero however long the model actually thought. It now counts from the first reasoning token to the first answer token, and it is reported the moment the answer starts rather than only when the whole generation is over.
- Math formulas no longer come out as a lump of red text. KaTeX was asked to render with `throwOnError: false`, which paints the source of any formula it cannot parse in red — one unsupported command such as `\label` turned the whole block into a wall of red. The commands KaTeX does not know but models write often (`\label`, `\nonumber`, `\notag`, `\usepackage`, `\documentclass`) are stripped before rendering, the LaTeX-native `\(...\)` and `\[...\]` delimiters are recognised next to `$...$` and `$$...$$`, a `$$...$$` block sitting inside a paragraph is recognised as a display formula instead of leaving stray dollar signs behind, and a formula that still cannot be rendered falls back to monospaced source rather than to red.
- The message list no longer falls behind the answer. The view was pinned to the newest line only when the text itself changed, so anything that resized the content afterwards — the reasoning panel unfolding, a webfont finishing its load, a formula re-laying out, an image arriving — left the view stranded mid-answer. A `ResizeObserver` on the content now re-pins the view whenever its height changes. The reasoning panel got the same treatment.
- The view stops following the moment the reader scrolls up, and it does not fight for the position afterwards. The wheel is read before the scroll happens, so the automatic pinning lets go first instead of snapping the reader back down. The floating button keeps the unread count visible, so nothing is lost while the answer keeps coming.

## [0.1.0] - 2026-11-20

### Added

- Streaming chat over Server-Sent Events against an OpenAI-compatible endpoint, with a blinking typing caret and buffered rendering at twelve flushes per second.
- A dedicated reasoning panel that keeps `reasoning_content` separate from the answer body, collapsible, with a "thought for X.X seconds" readout.
- Five reasoning effort levels: off, none, low, high, and max, sent as `reasoning_effort`.
- Full multi-turn conversation history sent back with every request.
- GitHub Flavored Markdown rendering with tables, sanitized through DOMPurify.
- Syntax highlighting for fourteen languages, with a working copy button on every code block.
- KaTeX rendering for inline and display math formulas.
- Regenerate, stop generation with an abort controller, copy an answer, and export a whole conversation as Markdown.
- Local conversation history in `localStorage`, grouped by today, yesterday, this week, and earlier, with new and delete.
- A settings panel covering connection mode, proxy URL, origin URL, API key, model, reasoning effort, temperature, top_p, max_tokens, system prompt, theme, and font size.
- A connection test and a proxy self-check against `/__ping`, reporting latency and whether the proxy holds a key.
- Light, dark, and follow-the-system themes.
- A persistent desktop sidebar and a mobile drawer, with soft-keyboard handling through `visualViewport`.
- A context usage meter based on a client-side token estimate.
- Conversation sharing through the URL hash, with no backend involved.
- A responsive layout that covers both phones and desktops.
- A zero-dependency reverse proxy in `proxy/`, running on Node, Cloudflare Workers, Deno Deploy, and Vercel Edge.
- Continuous integration for type checking, readme parity, and production builds.
- Automated deployment to GitHub Pages.
